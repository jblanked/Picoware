# Sprite3D Editor

The editor opens `.sprite3d` files from SD, renders them with the Pico Game
Engine, and creates and edits models, triangles, and vertices. It includes File,
View, Model, Select, Create, and Help dropdown menus.

Copy `builds/MicroPython/apps_unfrozen/Sprite3D Editor.py` and the complete
`builds/MicroPython/apps_unfrozen/sprite3d_editor/` folder into `/picoware/apps/`
on the SD card. For a lower-memory device installation, compile these sources
with the matching MicroPython mpy-cross version and deploy the resulting `.mpy`
files instead; generated bytecode is not included in this PR. The launcher and helper package must be installed together. Open **Sprite3D Editor** from
Applications, then choose **File > Open**. The selector starts in `/picoware/apps/games`; navigate into an
asset folder and select a `.sprite3d` file with Enter.

| Control | Action |
| --- | --- |
| Left / Right | Orbit around the model |
| Up / Down | Zoom in / out |
| 1 / 2 / 3 / 4 (4 View) | Select Top / Perspective / Front / Side |
| Z / Y | Undo / Redo an applied edit |
| W | Cycle viewport shading, also during transforms |
| G | Start Move or cycle Move / Scale / Rotate |
| O | Cycle Model / Triangles / Vertices / Edges / Islands |
| P (component selection) | Toggle camera controls; during transforms, change pivot |
| F5 | Toggle the active pane between full-screen and 4 View |
| R | Fit the model while retaining the selected view |
| Enter / Tab / F10 | Open or dismiss the menu bar |
| F / V / M / L / C / H | Open File / View / Model / Select / Create / Help |
| Arrows (menu open) | Switch menus or select an item |
| Enter (menu open) | Activate the selected item |
| Esc / Back | Cancel selection, dismiss an error, or exit preview |

The preview fits the model bounds automatically. A world-aligned X/Z grid sits
at the lowest vertex, with spacing shown in model units. Red marks X, green Y,
and blue Z in the orientation indicator. The grid and indicator follow orbit
changes and do not alter the asset. The default orbit is elevated to show ground
surfaces. Left/Right returns a fixed view to this orbit mode.

Fixed views use orthographic projection: parallel edges stay parallel and depth
does not change apparent size. They look toward the model center: Front from +Z, Side from +X, Back from
-Z, Top from +Y, and Bottom from -Y. Front/Side/Back keep +Y upward. Top keeps -Z
upward, while Bottom keeps +Z upward. Selecting a view also fits the model.
The orientation indicator marks an axis aimed into the screen with a cross and
an axis toward the viewer with a dot.

**4 View** displays Top, Perspective, Front, and Side simultaneously. Each pane
has a label, grid, and orientation indicator. Top uses an X–Z grid, Front an X–Y grid, and Side a Y–Z grid. These grids fill their panes and adjust display spacing to each pane’s zoom; snapping keeps the document grid step. Axis lines stay anchored at world zero. Perspective retains the ground grid. Top, Front, and Side are
orthographic; only Perspective uses perspective projection. A yellow border and highlighted numbered title mark the active pane. Press
**1–4** to choose Top, Perspective, Front, or Side. Left/Right rotates the
Perspective pane when it is selected; Up/Down changes only the highlighted pane’s zoom. Each pane remembers its own zoom, including across restarts.
Orthographic panes can zoom to 128 times the fitted size; Perspective stops
before the camera enters the model. Transformed geometry is clipped to each
pane. R fits only the active pane. **F5** enlarges the selected pane; press F5 again to restore 4 View with
the same pane selected. Perspective orbit and zoom changes carry back to the
four-pane layout without changing the other panes. Enlarged Top, Front, and
Side stay orthographic. F5 also works during Move/Scale/Rotate without applying
or cancelling the edit; 1–4 can select another pane while the tool is active.
Numeric-entry dialogs retain their normal keyboard controls. Choose another
View item to select a standalone view. Standalone orthographic views also support
128 times fitted zoom, with fitting based on actual bounds even for tiny models.
Tiny models also fit correctly in Perspective: only the temporary preview is
rescaled to avoid the renderer's fixed near plane. Saved dimensions are unchanged.
Use Up/Down to zoom (P first when navigating vertices or triangles), and R to fit.

The editor uses a separate transformed preview mesh for these views. View controls leave the source
mesh, its coordinates, and saved files unchanged. This does not require
camera API changes in the engine.

Files contain little-endian 40-byte triangle records: nine float32 coordinates,
an RGB565 uint16 color, one wireframe byte, and one ignored padding byte. The
loader preserves coordinates, colors, and per-triangle wireframe flags. It reads
800-byte chunks, rejects empty or incomplete records, invalid flags, nonfinite
or out-of-range coordinates (absolute value above 1e12), and models exceeding
the running engine's triangle capacity. A failed load retains the previous mesh.
Loading and viewing never change the selected asset.

## Dropdown menus

- **File:** Open, Save, Save As, Quit, New. New starts an empty document. Save
  and Save As require at least one triangle. Save asks for a path for a new
  document; otherwise it writes the current file. Save As asks for a full
  path or a filename in the current folder. A missing extension is added.
  An existing Save As destination requires confirmation before replacement.
- **View:** Camera (axis views, 4 View, Fit model), Shading (four display modes and Backface culling), Overlays (Base grid, Orientation, Vertex info, Normals, Edge lengths), Selection (X-Ray Selection).
  The active view is shown above the viewport. Checkmarks show enabled guides.
- **Model:** Move, Scale, Rotate, Undo, Redo, Color, Duplicate, Delete,
  Wireframe, Flip winding, Boolean submenu, Recalculate normals, Decimate. Editing actions use the current selection.
- **Select:** Model, Triangles, Vertices, Edges, All, None, Invert, Linked vertices, Connected solid, Islands (automatic).
- **Create:** New asset, Triangle, Plane, Box, Pyramid, Cone, Torus, Sphere,
  Cylinder, Capsule, Wedge, Octahedron, Face from vertices.
- **Help:** Controls, About.

The native engine serializes the current mesh; orbit, zoom, and guide settings
are excluded. Saving validates a temporary file before replacing the target,
preserves the original during replacement, and restores it if replacement
fails. On failure the document path stays unchanged. Use current firmware with
the documented 40-byte Sprite3D format; incompatible save output is rejected.

**Viewport shading:** press **W** to cycle Asset, Solid, Wireframe, and Solid + Wireframe, or
choose a shading item in View > Shading. Asset honors saved per-face wireframe
flags; Solid fills every face; Wireframe draws triangle edges; Solid + Wireframe adds contrasting edges over
filled faces using the native outline flag. Edge-only Wireframe is drawn by
the editor; disable Backface culling to show back-facing edges too. No extra mesh triangles are needed. These overrides
apply to single and four views and remain available during transforms. They do
not edit materials, mark the document dirty, or change saved files. Use Model >
Wireframe only when you intend to change the saved face flags.

**View > Shading > Backface culling** is enabled by default and saved to SD.
It excludes back-facing triangles before preview clipping and native allocation,
reducing the geometry processed on each frame. Disable it for two-sided display
of open or reversed faces. This also controls edge-only Wireframe; X-Ray selection
remains independent. Source winding, normals, saved geometry, and selection are
unchanged. Two-sided previews use triangle-centroid depth ordering; intersecting
faces can still show the native renderer's depth-order limitations.

**View > Overlays > Edge lengths** toggles tiny measurements at edge midpoints, in both
single and four-pane views. Values are model-space distances with two decimal
places (for example `02.00`), including triangle diagonals. Shared edges receive
one label. Labels update after edits; hidden, very short, off-screen, or crowded
labels are omitted. Zoom in to expose more detail. X-Ray Selection also allows
rear-edge measurements. The overlay starts disabled and its toggle is remembered.

## Saved editor preferences

Preferences are saved automatically to `/picoware/settings/sprite3d_editor.json`
on the SD card after a short pause in changes, and again when the editor closes.
They include display toggles, shading, view layout/orientation/relative zoom,
active pane and F5 state, selection mode and camera controls, linked vertices,
X-Ray, transform steps and snapping, creation color, palette/RGB mode, and the
last browsing directory. The view and selection settings are applied when the
first document is opened or created after startup. Opening another document
retains the editor's usual fit/reset behavior for document-specific controls.

Saving uses a verified temporary file and a recovery backup; a bad settings
file falls back to the backup or defaults. Preferences do not contain geometry
or replace File > Save for your asset.

## Selection and creation

Start with **Create > Box**, another primitive, or **File > Open**. File > New
(and Create > New asset) starts an empty document after checking unsaved edits.
New primitives are centered on the current model in X/Z, begin at the base-grid
height, and have a size of two grid cells. All their triangles are selected
automatically. Use Move/Scale/Rotate to position and size them precisely.
The new curved solids use shared seam vertices and outward-facing triangles,
so they form closed islands for Boolean operations and normals recalculation.
Their fixed starting resolutions keep creation small enough for the device:

| Primitive | Unique vertices | Triangles | Shape |
| --- | ---: | ---: | --- |
| Cone | 7 | 10 | 6 sides; base triangulated without a center vertex |
| Torus | 24 | 48 | 6 ring segments, 4 tube segments, open center |
| Sphere | 12 | 20 | Icosahedron with all vertices on the sphere |
| Cylinder | 12 | 20 | 6 sides; caps triangulated without center vertices |
| Capsule | 26 | 48 | 6 sides, two bands per rounded end |
| Wedge | 6 | 8 | Triangular ramp |
| Octahedron | 6 | 8 | Two square pyramids joined at their bases |

These are deliberately coarse, faceted starting meshes. Capsule end bands keep
its rounded-end silhouette distinct from a cylinder or pointed cone. Sprite3D
stores three corners per triangle; the counts above refer to shared positions.

Torus size is its outer diameter; its height is one third of that diameter.
Other new primitives use size as their height. Scale can change any proportions.
Creation respects the existing 2,048-triangle document limit and supports
SD-backed Undo/Redo.

Choose **Select > Edges** to pick unique shared mesh edges, including triangle
diagonals. Arrow keys navigate between visible edge midpoints; **Space** toggles
selection. **P** switches the arrows to camera controls. Comma/period cycle edges,
**I** enters an edge index, and All/None/Invert work from the Select menu.
The cursor edge is cyan; selected edges are yellow, with small midpoint markers.
**View > Selection > X-Ray Selection** exposes hidden edges for drawing and picking.
The mode works in four views and through F5, and is remembered at startup.

Move/Scale/Rotate affect both endpoints of each selected edge, including every
triangle corner sharing those positions, so adjoining faces stay connected.
Undo/Redo use the existing SD history. Delete removes the faces incident to
selected edges; it is not an edge-dissolve operation. Face-only commands such as
Color and Duplicate require Model, Triangles, or Islands mode.

Choose **Select > Vertices** for directional picking. **Arrow keys** jump to
the nearest vertex in that screen direction within the active pane. Candidates
must be inside a 90-degree sector and inside the viewport. Navigation stays at
the edge instead of wrapping. **Space** toggles the highlighted vertex and its
linked corners. **P** switches arrows between vertex navigation and camera
orbit/zoom, preserving your selection. During Move/Scale/Rotate, arrows continue
to control the tool. **1–4** and **F5** retain their view controls.

Vertices at the same screen position are skipped by directional navigation;
change the view or use **comma** (previous), **period** (next), and **I** to reach
overlapping corners. **View > Selection > X-Ray Selection** is off by default: vertices behind
mesh surfaces are hidden, and arrow/comma/period navigation and Space picking
respect this visibility. Enable X-Ray to see and pick through the mesh.
If orbit/zoom hides the cursor, the next arrow recovers a visible vertex near the
pane center. Entering Vertices mode or disabling X-Ray also recovers a visible
cursor. Toggling visibility preserves the selection, including hidden vertices;
All/None/Invert remain global selection commands and I remains a raw index jump.
Depth tests apply in every pane and shading mode, including wireframe. Compact
per-view visibility masks are cached in RAM and invalidated by geometry or
camera changes; no full-screen depth buffer or persistent geometry cache is added.

Choose **Select > Triangles** for face picking. **Arrow keys** navigate to the
nearest triangle center in that screen direction within the active viewport,
without wrapping at the edge. **P** switches arrows between triangle navigation
and camera orbit/zoom. **Space** toggles the highlighted face; navigation itself
does not change selected faces. The controls also work in four-view and F5 full
view. Coincident projected centers are skipped by arrows; **comma** (previous)
and **period** (next) browse faces by index; turn X-Ray on to include hidden faces.
The **slash** key also advances; left and right square brackets remain aliases.
Use **Space** to toggle a pick, **I** to enter a one-based index, **A** to select all,
and **N** to clear. Select > Invert reverses the selection. Cyan marks the
cursor, including a selected triangle; yellow marks other selected geometry.
The same X-Ray toggle controls triangle highlights and picking. With X-Ray off,
triangle centers are depth-tested against the model, matching directional
navigation. Faces whose centers are occluded are skipped, including in
comma/period browsing; partially covered faces use their center to decide.
Existing selections are retained, and the cursor moves to a visible face when
X-Ray is disabled. Island overlays remain see-through. Vertex indices refer to the three
packed corners of each triangle; selection is keyboard-based, not mouse picking.

The **Vertex info** overlay shows the selected vertex's model-space X/Y/Z
coordinates (two decimal places), updating live during transforms. It follows
the highlighted vertex when that vertex is selected; otherwise it shows the first
selected corner. **J/K** browses distinct selected positions in coordinate order,
wrapping at either end. Coincident selected corners share one entry; the panel
shows their linked count and the total selected corner count. Browsing changes
only the highlight. **B** hides/shows the panel, also available under **View > Overlays >
Vertex info**. In 4 View it sits diagonally opposite the active pane. It disappears
when there is no vertex selection. Coordinates remain model-space when the
camera rotates or F5 changes the layout. In full-screen views the panel shrinks
to four tightly spaced lines (vertex ID and X/Y/Z), with width fitted to the
values; J/K and B still work.

**Linked vertices** starts enabled: picking a corner also picks every corner
with exactly the same coordinates, keeping shared points together during edits.
Disable it to edit individual triangle corners. Changing this option clears
the vertex selection. Triangle transforms only move the selected faces and can
separate them from neighbors. Select > Model restores whole-model editing.

Use **Model > Duplicate** to copy selected faces in place; only the new copies
are selected, ready to move. **Model > Color** opens a visual selector with 32
palette swatches and Before/After previews. Arrows choose a swatch. **Tab**
switches to RGB controls: Up/Down chooses a channel and Left/Right adjusts it.
The channels display 0–255 values at the precision supported by RGB565. **H**
opens exact hexadecimal entry (0000–FFFF); accepting that entry returns to the
preview. **Enter** applies to the selected faces and sets the color for later
creation. **Esc** cancels without changing the mesh; from hex entry it returns
to the color selector. Color edits support Undo/Redo. **Wireframe** toggles each selected
face flag; **Flip winding** swaps its second and third corners. These face
actions require Model or Triangles mode. **Delete** (also the Delete key in
component mode) removes selected faces; in Vertices mode it removes incident
faces. Deleting everything leaves an editable empty document that cannot be
saved until geometry is added. All geometry changes support SD-backed Undo/Redo;
history navigation resets the selection to Model.

**Create > Face from vertices** joins exactly three distinct selected positions.
Collinear points are rejected. Corner index order determines winding; use
Flip winding afterward if needed. Creation uses the existing 40-byte format and
respects the native triangle limit.

## Decimate

**Model > Decimate...** reduces selected geometry using quadric-error edge
collapse. Enter the percentage of triangles to **keep**: `50` aims for half,
`25` for a quarter, and `100` leaves the count unchanged. Use Model mode for the
whole asset, Islands for a connected part, or Triangles for a face selection.

Calculation runs in small cooperative chunks with progress; **Esc cancels**
without changing the document. The result then enters a preview showing the
original count, actual count, and target. **W** changes shading; **F5** and
**1–4** let you inspect different views. **Enter applies** one SD-backed undoable
edit; **Esc restores** the original geometry and selection. Save persists the
reduced triangles. Operand captures are cleared when the preview is applied.

This is lossy simplification, unlike Boolean flat-region cleanup: surfaces can
change shape. The algorithm minimizes error against accumulated original face
planes. It protects open boundaries, color/flag seams, and vertices touching
unselected faces. Link and face-orientation checks reject collapses that would
pinch topology, invert faces, or create duplicate/degenerate triangles. It does
not detect all possible distant self-intersections; inspect intricate results.
Nonmanifold edges, duplicate faces, and inconsistent winding require repair
before decimation (use Recalculate normals for winding).

The target is a goal, not a guaranteed count: protected features, minimum closed
shell topology, two-face collapse steps, or the 32-pass work bound can leave more
triangles. The UI reports the actual result. Geometry/connectivity and compact
quadric arrays are temporary RAM working data; original snapshots and Undo are
on SD. Allocation failures cancel without modifying the document. The existing
**2,048-triangle input limit** still applies; this tool cannot import oversized
files. Simulator regressions include a 2,048-face sphere reduced to 1,024, open
boundaries, color seams, and untouched unselected islands; device timing and
maximum usable mesh size still depend on available device RAM.

## Face normals

**View > Overlays > Normals** toggles green arrows from triangle centers in all viewports,
including wireframe and four-view. They show the direction derived from vertex
winding and are drawn through the model so back-face normals can be inspected.
The overlay does not change the asset.

**Model > Recalculate normals** repairs every connected island touched by the
selection (all islands in Model mode). Neighboring faces get consistent winding;
each closed island is oriented outward using its signed volume. Open surfaces
keep their first face's direction, since they have no defined inside/outside.
Use **Flip winding** to choose the opposite direction on an open surface.
Nested closed shells are oriented outward individually; cavity shell intent is
not inferred automatically.

Sprite3D stores vertex order rather than separate normals. Recalculation swaps
vertices where needed, preserving positions, colors, flags, and triangle count.
The change uses SD-backed Undo/Redo and persists through Save. A no-op adds no
history entry. Degenerate faces, nonmanifold edges, or conflicting orientation
abort the operation without changing the document; this action does not repair
topology or self-intersections.

## Boolean operations

The editor supports **Union**, **Difference (A minus B)**, and **Intersection**
of closed, consistently wound solids, including concave meshes such as a torus.
Each operand may contain up to **512 triangles**, so all standard primitives
can be assigned to A or B. Valid concave results can be reused for another cut.
Planes, open meshes, inconsistent winding and oversized operands are rejected;
input surfaces must not intersect themselves.

All Boolean operations and operand controls are grouped under **Model > Boolean**.
**Right** or **Enter** opens the submenu; **Left** or **Esc** returns to Model.
Up/Down selects an entry and Enter runs it.

For a document containing exactly two islands, choose **Model > Boolean > Union A + B**,
**Difference A - B**, or **Intersection** directly. No operand capture is needed.
For Difference, the active island in Islands mode is A (the part to keep);
otherwise the first island in file order is A.

Use **Select > Islands (automatic)** to select an entire connected part.
**Left** selects the previous island; **Right** selects the next,
wrapping at the ends. The active island is cyan and its number appears in the
header. Move, scale, rotate, color, and delete work on its selected faces.
Browsing replaces the selection with that island; Space toggles the whole island.

Islands are detected from exactly matching shared edges, regardless of face color.
Overlapping parts remain separate if they do not share edges; touching at a single
vertex does not join them. Welded parts cannot be inferred as separate objects.
Only compact face-index groups are cached in RAM, invalidated by geometry changes;
geometry backups, captured operands, and Undo remain on SD.

For more than two islands, or to choose the operands explicitly:

1. Select island A, then **Model > Boolean > Set operand A**.
2. Browse to island B, then **Model > Boolean > Set operand B**.
3. Choose the operation. **Clear operands** returns to automatic two-island mode.
   The older **Select > Triangles > Connected solid** workflow also remains available.

After every Boolean, compatible coplanar regions are merged and triangulated
without unnecessary center vertices. Colors, face flags, sharp edges, holes, and
shared boundary junctions are retained. The preview shows the triangle count
before and after cleanup. This is shape-preserving cleanup, not a target-count
approximation: some results cannot be reduced further. For overlapping same-color
boxes, the union test drops from 64 generated triangles to 12.

Inspect the preview. **F5**, **1–4**, and **W** retain their view/shading
controls. **Enter** applies one undoable edit; **Esc** restores the original
geometry and selection. Other geometry edits and saving wait until Apply/Cancel.

The header shows A/B face counts. The two operands must use different faces.
Captures are verified SD snapshots; adding or editing unrelated faces is fine.
If a captured face changes or its index shifts, recapture that operand before
running the operation. **Clear operands**, opening/new documents, and closing
release these snapshots. Applying clears A/B; cancelling retains them.
Only operand faces are replaced; other geometry remains in the document.
Colors/outline flags follow their source faces, including B's cut surfaces.
An empty result is valid and undoable, but empty documents cannot be saved.

The calculation uses temporary RAM for geometry and SD for captures/backups.
Calculation runs in small batches with progress shown in the footer. **Esc**
cancels without changing geometry or selection; after calculation, Enter applies
the preview and Esc discards it. Work, tree depth, fragments, 30 seconds of
active calculation time, and output size (2,048 triangles) are bounded. Intersections use a relative tolerance of 1e-5 of
the combined bounds. Degenerate or nonmanifold results are rejected before
preview installation. Tiny details near that tolerance may require resizing or
moving the cutter. This is a small-solid tool, not a general mesh repair system.

BSP operation sequences are adapted from [Evan Wallace's csg.js](https://github.com/evanw/csg.js)
under the [MIT license](licenses/csg-js-MIT.txt).

## Transforms

Select **Model > Move**, **Scale**, or **Rotate**. The tool displays X/Y/Z values
and live geometry in every view. Only the selected model, faces, or vertices
change. Pivots use the selected bounds. Move uses model units, Scale uses factors
(1 means unchanged), and Rotate uses degrees. The camera and base grid remain
fixed while editing. Use **View > Camera > Fit model** afterward to frame the result.

- **Left/Right:** select X, Y, or Z in Move, Scale, and Rotate. Move skips the depth axis in orthographic
  views: Front/Back use X/Y, Top/Bottom X/Z, and Side Z/Y. The Move indicator
  shows only those two axes; switching panes updates the selected axis.
  **Up/Down:** increase/decrease that value. Move steps by
  one tenth of the grid spacing, Scale by 0.1, and Rotate by 5 degrees initially.
- **T:** enter an exact adjustment step. **-/+:** divide/multiply it by ten
  (`=` also increases it). Steps are remembered per tool until another file
  is opened. The header shows the effective step.
- **S:** toggle snapping for arrow adjustments. Move aligns the selected pivot
  to the world grid, with at least one grid cell per adjustment. X/Z snap to
  world-zero grid lines; Y snaps relative to the base-grid height. Rotation
  snaps to multiples of its step; Scale snaps in steps relative to factor 1.
  Enabling snapping alone does not move the model.
- **E:** enter an exact value with the standard keyboard. Enter accepts the
  value; Esc cancels numeric entry. Scale factors must be positive and at most
  1,000,000. Nonfinite values and coordinates outside the format's supported
  range are rejected. Exact values bypass snapping.
- **U:** toggle linked XYZ scaling. Scale starts linked; unlink to change axes
  independently. Linking copies the selected axis value to all axes.
- **P:** cycle Center, Bottom center, and World origin pivots for Scale/Rotate.
  For Move, choose Center or Bottom center as the grid-snap reference. Center
  and Bottom center use the bounds at the start of the operation.
- **Enter:** apply the transform. **Esc:** restore the geometry before the tool
  opened. **Model > Undo/Redo**, or **Z/Y** outside a tool, traverses applied edits.

Move arrows, square scale handles, and rotation rings show world axes on the
model in each view. Red is X, green Y, and blue Z; yellow highlights the selected
axis (all axes for linked scaling). These are visual indicators for the keyboard
controls, not mouse drag handles. Rotation applies X, then Y, then Z about the
selected pivot, always calculated from the operation's original coordinates.

An asterisk marks unsaved edits. Open, New, and Quit ask before discarding edits.
Save writes the transformed float32 vertices while preserving triangle colors
and wireframe flags; no engine API or file-format change is needed. Cancel and
Undo/Redo use verified SD snapshots. Returning to the saved history state clears
the unsaved marker; a new applied edit after Undo discards the Redo branch. If clipping would exceed the native triangle limit, the
editor retains the previous preview and reports the failure.

## SD cache and history

The editor keeps transform backups and up to 16 Undo/Redo snapshots in its own
session folder under `/picoware/cache/sprite3d_editor/`. RAM holds a small index
of filenames, sizes, checksums, and revision IDs. Transform previews stream
original triangles from the SD backup in 800-byte chunks. The active model and
native rendering meshes remain in RAM because the current engine requires them.
No extra snapshot is written for each preview keypress. Selection uses a small
RAM byte mask (at most three bytes per triangle); there is no persistent
RAM topology cache. Empty-document history entries need only a small sentinel.

Writes are verified before the backup is accepted; reads check length and CRC32.
An SD failure leaves the current preview and history position unchanged and
reports an error. Restoring the SD access allows retrying or cancelling. Saving
and history caching use separate files: editing never overwrites the source asset.
Cancel removes the pending backup, discarded/expired history files are removed,
and opening another document or closing the editor cleans up the session cache.
History is session-only; an interrupted session can leave temporary files in
this cache folder, not a recovered editing session.

## Simulator

From the repository root:

```sh
sh tools/run-micropython-desktop.sh --viewer --audio silent --network offline \
  --sd /tmp/sprite3d-editor-sd --app 'Sprite3D Editor'
```

Put sample assets under the simulator SD's `picoware/apps/games` directory.
The simulator installs app sources from `builds/MicroPython/apps_unfrozen`.

## Source layout

The application launcher is `apps_unfrozen/Sprite3D Editor.py`. Its
`sprite3d_editor/` package contains:

- `assets.py`: record validation, transforms, bounds, and safe file saving.
- `viewport.py`: native preview geometry, pane selection, F5, grids, and gizmos.
- `ui.py`: menus, status bars, and dialogs.
- `editor.py`: document state, input routing, and lifecycle.
- `transforms.py`: transform tools, exact entry, step sizes, and snapping.
- `history.py`: SD cache snapshots, Undo/Redo, and saved-state tracking.
- `selection.py`: component masks, linked vertices, browsing, and overlays.
- `creation.py`: primitive geometry and validated triangle construction.
- `editing.py`: transactional geometry edits, creation, and exact-value entry.
- `colors.py`: palette, RGB sliders, hexadecimal entry, and color previews.
- `edges.py`: tiny, clipped edge-length annotations.
- `preferences.py`: validated SD settings, automatic saves, and startup restoration.
- `csg.py`: cooperative Boolean geometry and closed-mesh operand validation.
- `cleanup.py`: coplanar merging and boundary-preserving triangulation.
- `islands.py`: automatic edge-connected island detection.
- `normals.py`: face-normal overlay and connected-island winding repair.
- `visibility.py`: sparse depth testing for visible-only vertex display/picking.
- `decimate.py`: cooperative quadric-error simplification and SD-backed preview.
- `booleans.py`: connected-solid selection, SD operand capture, and preview/apply/cancel.

Compiled counterparts live under `builds/MicroPython/apps/`. The simulator
loads the source launcher and package together. No engine changes are required.

Menus open with focus on the top bar. Left/Right switches headings; Down or Enter
enters the dropdown. Enter or Right opens a submenu. Left/Esc returns from a
submenu. Up/Down wraps between the first and last items in every dropdown and
submenu. On the top bar, Down/Enter enters the first item and Up enters the last.
Left/Right wraps between File and Help. Esc in a dropdown or on the top bar closes menus.

Triangle Move/Scale/Rotate honors **Select > Linked vertices** (enabled by default).
With linking enabled, all corners at each selected vertex position move together,
keeping adjoining faces connected. Disable linking only to detach a face deliberately,
for example when moving a coincident duplicated triangle. Face selection, color, and
delete operations still apply only to the selected triangles.

**G** starts Move on the current selection, then cycles Move → Scale → Rotate → Move.
Switching applies the current adjustment as an Undo step and starts the next tool
with neutral values. Selection, axis (where permitted), and pivot are retained.
Esc cancels only the current adjustment; Undo can reverse earlier applied tools.
Cycling without changing geometry does not add Undo steps. G remains normal text
input in numeric and filename dialogs.

**Model > Cleanup > Remove degenerates** removes triangles collapsed to a point or a
straight line from the whole document, with Undo/Redo support. Sprite3D stores
only triangle corners, so there is no separate pool of unused vertices; removing
these records also removes their stray selectable corners. Valid isolated pieces
and thin triangles remain unchanged. A clean model produces no Undo entry.

**O** cycles Model → Triangles → Vertices → Edges → Islands → Model outside
menus and active edits. It uses the same selection reset as choosing a mode from
Select. **P** toggles component navigation versus camera arrows in Triangles,
Vertices, and Edges; Q no longer toggles the camera. During Move/Scale/Rotate,
P retains its pivot control and O leaves the active edit unchanged.

**Model > Cleanup > Remove duplicates** removes repeated faces across the whole document,
keeping the first copy. It matches exact vertex positions in cyclic order, plus
color and wireframe setting. Reversed winding and differing materials are retained
to preserve intentional two-sided surfaces. Nearby vertices are not welded.
Undo/Redo restores/removes the duplicates; a clean model adds no Undo entry.

Numeric coordinate and transform readouts use two decimal places. Very small
nonzero values and large values use scientific notation with two decimal places.
This affects display only: geometry keeps its full precision, and accepting an
unchanged numeric field preserves its original value. You can still enter more
precise values when editing.

Preview rendering reuses unchanged panes and keeps visibility/edge-label caches
separate for each viewport. Idle editor frames do not redraw; Boolean and decimation
progress redraws are limited to ten per second, with completion shown immediately.
Four-view transforms defer the unused full-screen preview until it is needed.
Visibility checks explicitly collect garbage only when free Python heap falls
below 32 KiB; automatic MicroPython collection remains enabled. Undo snapshots
remain on SD.

Filled previews sort faces from far to near with backface culling both on and
off, so rear objects do not overwrite nearer objects merely because of file
order. This is painter ordering, not a per-pixel depth buffer; intersecting
triangles can still require splitting for exact occlusion. Pure Wireframe and
X-Ray selection retain their existing display behavior.

Rendering computes each face depth once before sorting. Coincident vertex markers
are combined with selected/cursor priority, while wireframe draws each shared
edge once. Face normals and projected wire/normal line commands are cached on SD;
these disposable caches are invalidated after geometry edits and released on
close. SD cache failures fall back to drawing without changing the asset.

For meshes above 256 triangles, interactive component visibility is calculated
in small batches, prioritizing the active viewport. While a pane is being checked,
its component markers are withheld and cannot be picked; the model and camera
remain usable. The hint reads "Checking visibility...". Changes of camera,
geometry, layout or selection mode discard obsolete results. The scheduler aims
for 6 ms of visibility work per update, but allocation and garbage collection
can exceed that budget; it is not a hard real-time guarantee.
